# From one result to a working system

Progress at the learner's pace. These are practice stages, not a promise of completion in a fixed number of sessions.

| Stage | Practice | Evidence to move on |
| --- | --- | --- |
| First result | Pick one task; use a small permitted sample; make an artifact | Output checked against 2–3 criteria |
| Better context | Add a rule, source, and good example | Learner can explain which information changed the result |
| Repeatable work | Run on a different input and add exception checks | Normal, missing-data, and conflict cases recorded |
| Reusable procedure | Extract successful steps into templates/skill.md | Procedure works on another case |
| Several projects | Add a registry and shared definitions only where useful | Agent selects the right context without mixing projects |
| Team handoff | Use templates/handoff.md | A colleague repeats the workflow independently |
| Optional integration | Use templates/integration.md | Access, read-only test, reviewer, and failure path verified |

Try these follow-up prompts:

> Help me test the same workflow with a new input. Keep the old result for comparison.

> Turn our successful procedure into a short reusable instruction. Include the exceptions we found.

> Help me add a second project. Keep its data separate and identify what can actually be shared.

> Prepare a handoff so a colleague can reproduce this without reading our chat.

If a new step does not help a real task, skip it. Integrations, code, GitHub, and schedules should solve a demonstrated need.
