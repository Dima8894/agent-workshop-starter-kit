# Bring the practice into a team

Use this kit after a workshop or as an independent internal learning resource. Each participant works on a real type of task with fictional or approved data. The shared outcome is the ability to repeat and verify work, not the number of prompts written.

## Three phases

**From task to result:** participants define one meaningful task, assemble context, create an artifact, and check it. A facilitator demonstrates once, then helps only where the learner is stuck.

**From result to process:** participants test new inputs and exceptions, document a reusable procedure, and organize additional projects. Reduce guidance so they can explain the method themselves.

**From project to team:** colleagues exchange handoffs, reproduce results, and build a project map with owners and open issues. Evaluate whether tools, integrations, or further development are actually needed.

This follows the direction of Alpes team learning while keeping the open-source resource independent of commercial schedules, pricing, and enrollment.

## Roles and adoption

| Role | Responsibility |
| --- | --- |
| Learner | Chooses the task, supplies permitted context, checks the result |
| Facilitator | Demonstrates, asks useful follow-ups, removes unnecessary complexity |
| Domain reviewer | Confirms business rules and acceptance criteria |
| Tool/data owner | Approves access and data handling for connected systems |
| Team lead | Selects useful processes and reviews evidence of adoption |

Start with one low-risk process. Agree what data may enter the selected AI tool. Keep workspaces private by default. Use a separate sanitized copy when sharing a teaching example.

## A facilitation session

1. Ask the learner to explain the desired output in their own words.
2. Demonstrate one comparable fictional example.
3. Let the learner work on their case; intervene with a question rather than taking over.
4. Review an actual output and an exception case together.
5. End with a checkpoint and one next action.

## Measure what happened

Record baseline task time if available, assisted run time, correction time, number of unsupported claims, whether a new input works, and whether another person can reproduce it. Keep sample size and data conditions beside each observation. Do not report estimated savings as measured ROI.

Progress badges are optional private feedback. Do not rank employees by them or require publication of individual results. Collect only the learning evidence the team needs.

## Before live automation

Use the integration readiness template. Begin with least-privilege read access, test failure paths, preview any write, and obtain the required authorization. Define the owner, rollback, and stop switch before scheduling. A workshop exercise is not production approval.
