# Example interview

This is a scripted illustration using fictional data, not a transcript of a user study.

**Assistant:** Have you brought a worksheet, do you have a task in mind, or would you like an example?

**Learner:** I check deliveries. I would like a report of late ones.

**Assistant:** What do you look at first when you check a delivery?

**Learner:** Whether it is completed. If not, I compare the planned date with today.

**Assistant:** If the planned date is missing, what should the report do?

**Learner:** Ask for it. Don't guess.

**Assistant:** We can try this with three fictional deliveries and a fixed review date. The report should cover all three, calculate delays correctly, and flag the missing date. Does that match your rule?

**Learner:** Yes. Please make the report.

**Assistant:** [Reads the example input and creates a separate report.] TEST-01 is two days overdue. TEST-02 is completed; this rule does not tell us whether it was completed on time. TEST-03 needs a planned date. Let's compare these statements with the three input rows.

**Learner:** That makes sense. Can we run it every Monday?

**Assistant:** First let's repeat it with another sample and check what happens when two sources disagree. A schedule needs a separate setup and permission; nothing is scheduled yet. I saved the current rule and the next check.

The assistant earns no badge merely by writing the words above. In a real session, the report must exist and the checks must be performed.
